# 質問紙内容の補足レビュー

対象：`independent-review-input/questionnaire-supplement.json`（protocol: recipient-20260921-v7.2、questionnaire: questionnaire-20260921-v4）と、先に許可された `independent-review-input/methods-measures.html` のみ。追加資料に基づく別記録であり、先の独立初読レビューは変更していない。外部検索、原尺度の原文照合、実装確認、人間による認知面接は行っていない。以下の修正文は検討候補であり、既存尺度と同等の内容妥当性を確認した文言ではない。

## 総合判断と確認範囲

質問紙は、十分さ、表面的完成度、信頼、負荷、文書知覚、責任帰属、AI開示の認識を概ね区別している。項目IDのある57定義を確認した。同じ信頼4項目が2ブロックにあるため、固有IDは53である。さらに理解確認2問、テーマ確認1問、年齢・性別、回答UIと案内文を確認した。理解確認にはIDが付されていないため、以下ではJSON上の `precheck[0]` と `precheck[1]` で指定する。

収集版の固定前に特に判断したいのは、①「補う」を修復全般とみなしてよいか、②送り手の事情や自分の影響を判断できない回答者をどう扱うか、③編集前の完全性6項目と反復される責任・知覚質問の役割、④「正解なし」案内の例外、⑤主観負荷に途中の評定負担を含めるか、である。文言だけで直る事項と、研究上の測定対象を決めなければ直せない事項を分ける必要がある。

判定は **維持**＝現時点で明瞭な改変理由がなく採用を維持、**文言**＝概念を大きく変えない修正文を検討、**判断**＝構成概念・選択肢・分岐・測定時点の決定が必要、とする。「維持」は妥当性検証済みを意味しない。重要性は **高**＝収集版固定前、**中**＝分析仕様または理解しやすさの確認時、**低**＝任意の改善とする。

## 優先して判断する横断的な問題

### 1. 「判断できない」をなくしても、判断可能性は確保されない【高】

JSONの `questionnaire.rating` は「『判断できない』を廃止」「主要指標の欠測を避ける」と説明し、UIも初期選択なし・unknownなしとしている。自分の印象を尋ねる項目では、その時点の印象を回答してもらう運用は可能である。しかし `sender_control` は描写されていない送り手の時間・能力・機会を推測させ、`responsibility_influence` と `disc_influence` は本人にも因果的影響が分からない場合がある。回答が埋まることと、意味のある回答が得られることは別である。

「影響なし」「判断できない」「そのことを考えなかった」「修正の必要がなかった」を同じ中点や低得点に押し込めない方針が必要である。判断不能や非該当を設ける場合は数値得点に混ぜず、発生率と欠測規則を事前指定する。強制選択を維持するなら、印象を尋ねる範囲を明示し、推測の不確かさを含む評定であると報告する。元尺度との一致は本資料だけでは確認できず、それを理由に一律の選択肢方針を正当化することはできない。

### 2. 「補う」は一般化の修正を十分に含まない【高】

`repair_need`「内容を補う必要」、`recipient_duty`「自分が補って」、`repair_reluctance`「不足を補う」は、情報の追加を連想させる。一般化条件では断定の削除・弱化、焦点ずれ条件では方針への書き換えが必要になりうる。補完に限定した認知を測るなら現行でもよいが、修復全般の必要性・責任・抵抗として解釈すると条件により測定範囲がずれる。

修復全般を対象とする場合の共通語は「内容を修正する」とし、`repair_need` は「依頼に応える報告書にするため、最初の報告案の内容を修正する必要があった」を候補とする。「追加・削除・書き換えを含む」という説明を付けるなら、提出後ブロックに限定しても次案件を訓練する点は残る。文言と時点を合わせて判断する必要がある。

### 3. 主要6項目は「完全性」を測るが、繰り返しと日本語の絶対性が強い【高】

`suff_1`「すべて」、`suff_2`「不完全」、`suff_3`「完全」、`suff_4`「十分に完全」、`suff_5`「カバー」、`suff_6`「広さと深さ」は近い内容を連続して問う。一致度が高くても、重複や同じ語の反復の結果である可能性を区別すべきである。とくに資料に今回対象の未確定事項がある課題で、回答者が「完全」を「今後の追加調査が不要」と理解すれば、今回の方針決定には十分な基準文でも低くなる。

ブロックの冒頭に「今回依頼された調査・試行の方針を考えるための情報として」と評価範囲を明示する案がある。ただし、現在の主要概念を変える可能性があるため、安易に6項目を短縮したり、すべてを「十分」に置換したりしない。6項目の原尺度との対応を別途確認し、認知面接で各項目の言い換え、判断不能例、基準文でも低く答える理由を確認して決める。

### 4. 反復される質問自体が次案件の検討枠組みを教える【高】

各案件の41評定・質問のうち、編集前に12項目、提出後に29項目がある。これに理解確認2問とテーマ確認1問を加えて44項目を4回繰り返す。`perc_5` は適用範囲の検証を、`sender_blame` 等は送り手の責任への注目を教える。編集前の信頼には直前の十分さ評定の影響、提出後の責任帰属には直前の詳細な知覚評定の影響がありうる。順序が一貫していることは再現性の利点だが、自然な初読・編集の順序とは同一ではない。

本パイロットで現行順序を保つ場合は、その反応性を含む課題として位置別の分布・所要時間・誤答・離脱を記述する。負担を減らす次版では、主要得点を場当たり的に削る前に、探索的な責任項目を毎回測る必要、MCを別標本で測る必要、信頼の前後測定の優先度を決める。質問順の変更や削減は収集中に行わず別版とする。

### 5. 理解確認と「正解・不正解はありません」の適用範囲を揃える【高】

`UI.consentAnswer` は「本調査には正解・不正解はありません」とするが、`precheck[0]`・`precheck[1]` は正答するまで先へ進めず、「答えが説明と合っていません」と表示する。`readcheck` にも正答が定義される。これは質問紙の説明として直接的な不整合である。

案内の修正候補は「報告案への評価や感じ方を尋ねる質問に、正解・不正解はありません。説明や案件の内容を確認する質問には、説明に対応する答えがあります。回答や提出内容の良し悪しで報酬が減ることはありません。」。最後の報酬文は現行の条件を保持した候補であり、報酬運用そのものは本レビューでは検証していない。

### 編集前の十分さ・表面的完成度

`cognition.instruction` の「報告案に書いてあることだけを評価」は、資料から自分で補った情報を混同させない点で有用である。ただし、同じブロックの送り手への信頼にも一律に適用すると、送り手の名前しか書かれていない文書から何を評価すべきか曖昧になる。十分さ・完成度と信頼の間に小見出しを置き、信頼には「この報告案を受け取った今の印象で、{sender}さんについて答えてください」と対象を切り替える案がある。

| `sender_duty` | 維持・中 | 送り手の規範的責任として明瞭。ただし渡すものが「下書き・報告案」で受け手に仕上げ役が明示されるため、誰がどこまで仕上げるべきかの個人差を含む。望ましい回答や正答を設定しない。 |
| `sender_control` | 判断・高 | 「確認し、必要な修正をすることができた」は確認能力、修正能力、時間・機会をまとめる。送り手の事情は示されていない。知覚された統制可能性を測るならその範囲を明示し判断不能を扱う。必要なら能力と機会を分けるが、負担増に見合う分析目的を先に決める。 |
| `sender_unfinished` | 文言・中 | 「自分が引き受けた作業」は上司からの役割全体とも読める。候補「今回、自分が行った確認・修正の中には、{sender}さんが渡す前に済ませるべきだった作業があった」。実作業を問うか、放置した未処理作業も含むかで現行との範囲差を確認する。 |
| `sender_blame` | 維持・中 | 落ち度を問うこと自体は責任非難の測定目的に沿う。中立化して「問題がある」にすると別概念になりうる。先行する責任質問に誘導される可能性を含む事後評価として扱う。 |
| `recipient_duty` | 判断・高 | 「不足」「補う」の範囲が狭い。修復全般なら「報告案に修正が必要な点があれば、自分が直してから提出する責任があると思った」。課題教示への同意と自発的責任感を区別できないため、行動の因果的説明に直結させない。 |
| `task_value` | 維持・中 | 課題の主観的重要性として明瞭。社会的に望ましい回答に偏る可能性はあるが、それだけで削除しない。金銭的価値・職務上の利害を測ったとは解釈しない。 |
| `repair_reluctance` | 判断・高 | 修正不要の場合、「抵抗を感じなかった」と「場面がなかった」を区別できない。「代わって」も送り手の仕事を引き受けたと前提化する。補完への抵抗を維持するなら非該当を用意。一般の修正抵抗なら「この報告案を自分で修正することに、抵抗を感じた」を候補とし、代行への抵抗から概念が変わることを明記。 |
| `responsibility_influence` | 判断・高 | 責任を考えたこと、影響があったこと、その方向をまとめて回顧させる。確認は増やし修正は減らした場合や、増減が相殺された場合に単一値を選べない。本人の認識する総合方向として残すなら「全体として」を明示し、考えなかった／判断できないを中点と分ける。機序の主要指標にするなら、考慮の有無と行動別の方向を分ける構成判断が必要。 |
| `resp_free` | 文言・中 | 現行は責任を捉え、行動に関係したことを前提化する。候補「4件を通して、同僚の責任について考えたことがあれば教えてください。確認・修正の仕方との関わりを感じた場合は、その点もお書きください。考えなかった、関わりは感じなかったという回答でもかまいません。」任意性は維持。 |

## 得点化・回答UIとの整合

十分さの `suff_2`、信頼の `tr_1` と `tr_3` を1–7で逆転する8−xは文の方向と整合する。`ptt_2`は否定表現でも信頼を肯定する文であり、逆転しない現行設定が整合する。信頼4項目が同じIDで前後に存在するため、分析ではブロック・案件を含めて識別し、IDだけで上書き・合算しないことが必要である。実装にその誤りがあると確認したものではない。

RTLXは0–100・5刻みで、6下位尺度を無加重平均する説明と対応する。`tlx_op`は高いほど悪い向きなので追加逆転は不要である。6下位尺度には要求、努力、自己評価、感情が含まれ、すべてが単一の精神的努力を測る項目ではない。`effort_total`と別に報告する方針は維持する。項目を短縮・削除した場合に同じRTLXとして扱えるかは別途判断を要する。

スライダーは初期位置50でも「未回答」と表示し、触れるまで送信できない。この追加仕様により、初期値50が自動的に回答として保存されるという懸念は解消される。ただし中心位置の視覚的な基準効果、50を意図した回答者がどう確定するか、クリック・キーボード・タッチで確実に回答できるかは実UIでの確認が必要であり、本レビューでは試していない。

同意評定1–7、努力0–10、TLX0–100、影響0–6を頻繁に切り替えるため、端点は項目ごとに視認できる必要がある。`responsibility_influence` と `disc_influence` は3が「影響なし」の双極尺度であり、一般の同意尺度と同方向の点数として合算できない。責任・知覚項目を別々に扱う現行方針は妥当である。unknown・非該当を追加する場合は、十分さの「全項目有効時に平均」というルールも含めて再指定する。

## 回答負担・測定時点についての判断

通常の192回答は、背景9、毎案件の尺度等41×4、理解確認・テーマ確認3×4、最後7で説明できる。任意記述2項目、年齢・性別・同意は別で、理解確認の再試行で増える。1～7尺度が多いだけでなく、同じ完全性の言い換え、信頼の前後反復、類似する努力・責任・影響の評価を4案件で求める点が負担の中心である。表示された「30〜60分」は見込みであり、人間の完了時間を検証した結果ではない。

順序は `materials → read → cognition → edit → post → trust_post → perception → responsibility` と確認できた。提出後の信頼が責任非難の質問より前にある点は、直前の非難質問による誘導を避ける方向に働く。ただし負荷評定の後であること、以前の案件ですでに責任質問を経験していることは残る。十分さ→信頼→行動の順序は媒介的な筋道を調べやすくする一方、測定がその筋道を作る可能性がある。

最後の `memory` はAIに関する他の質問より先なので、直前のAI影響質問に誘導された想起を避ける順序である。一方、`belief` はAI表示の選択肢を見た後の回顧であり、作業時のAI推測を直接記録したものではない。`resp_free` も既に4回責任質問を受けた後の記述で、自発的に責任という観点が生じた証拠にはならない。

パイロットでは、項目・ブロックの所要時間、項目位置と同一回答の連続、前後の極端な反転、理解確認の再試行、テーマ誤答、離脱を記述する。ただし同一回答の連続や逆転項目間の不一致だけで不注意と判定しない。重複項目が似た回答を生むこと、正当な判断の揺れ、文章の理解差を区別する。項目削除や除外の基準は結果を見て効果を大きくする方向に選ばない。
